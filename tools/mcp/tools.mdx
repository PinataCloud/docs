This page documents all tools available in the Pinata MCP server. Each tool includes its parameters and example prompts you can use with Claude.

## Hosted and local

The [hosted server](/tools/mcp/hosted) and the local `pinata-mcp` server share their tools and tool names. The tables below describe the local server; where the hosted server differs, a **Hosted server** note says how.

- **Local server only:** [uploadFile](#uploadfile), [uploadFolder](#uploadfolder) and [listAllowedDirectories](#listalloweddirectories), which read your disk.
- **Hosted server only:** [uploadContent](#uploadcontent), [uploadFolderContent](#uploadfoldercontent) and [listGateways](#listgateways).
- **Network on the hosted server:** uploads, searches, lists, new groups and links need `network`. Tools that take a file or group ID find it on either network when `network` is left out.
- **Gateway on the hosted server:** link and fetch tools take an optional `gateway` (one of yours, or one of its custom domains) and default to your account's first gateway.
- **Results on the hosted server** are the record itself, without the API's `data` wrapper; an action with nothing to return answers `{"success": true}`.

## File Operations

### uploadFile

<Note>
  Local server only. On the hosted server, use [uploadContent](#uploadcontent) for content the assistant has, or [createSignedUploadUrl](#createsigneduploadurl) for files on your disk.
</Note>

Upload a file to Pinata IPFS. Provide either a file path or base64-encoded content. Files over 90 MiB are sent as [resumable uploads](/files/uploading-files#resumable-uploads).

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `resourceUri` | string | No | File URI to upload (e.g., `file:///path/to/file.jpg`) |
| `fileContent` | string | No | Base64-encoded file content (alternative to resourceUri) |
| `fileName` | string | No | Name for the uploaded file (auto-detected from path if using resourceUri) |
| `mimeType` | string | No | MIME type (auto-detected if not provided) |
| `network` | `"public"` \| `"private"` | No | Upload to public or private IPFS (default: `"public"`) |
| `group_id` | string | No | ID of a group to add the file to |
| `keyvalues` | object | No | Metadata key-value pairs |
| `waitForCid` | boolean | No | Files over 90 MiB only. By default the upload waits until Pinata has registered the file and returns its full record. Set to `false` to return once the bytes are stored: the result then holds only `cid` (empty if not known yet) and `size`, and registration can still fail (default: `true`) |

**Example Prompts:**
```
Upload the file at ~/Documents/report.pdf to Pinata as a private file

Upload this image to my Pinata account as a public file named "My Logo"

Upload ~/data/config.json to Pinata and add it to group abc123
```

### uploadContent

<Note>
  Hosted server only.
</Note>

Upload content the assistant has in hand (text it wrote, JSON, a small image as base64) as one file, up to 2 MiB. For files on your disk or anything larger, use [createSignedUploadUrl](#createsigneduploadurl).

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `filename` | string | Yes | Name of the file, e.g. `report.json`; no `/` (use [uploadFolderContent](#uploadfoldercontent) for paths) |
| `content` | string | Yes | The file content: plain text, or base64 when `encoding` is `"base64"` |
| `encoding` | `"utf8"` \| `"base64"` | No | How `content` is encoded (default: `"utf8"`) |
| `network` | `"public"` \| `"private"` | Yes | Public: anyone with the CID can read it, and copies may outlive a delete. Private: only through signed links |
| `group_id` | string | No | ID of a group to add the file to |
| `keyvalues` | object | No | Metadata key-value pairs (at most 9) |

**Example Prompts:**
```
Write a JSON summary of this conversation and upload it to Pinata as a private file

Upload this SVG logo to Pinata as a public file named logo.svg
```

<Note>

## Folder Operations

<Note>

### uploadFolder

<Note>
  Local server only. On the hosted server, use [uploadFolderContent](#uploadfoldercontent) for files the assistant has, or [createSignedUploadUrl](#createsigneduploadurl) for a folder on your disk.
</Note>

Upload a local directory as one folder with one CID, subdirectories included. Use it instead of `uploadFile` whenever the content is a directory (a website, a dataset, a set of images). Each file is its own resumable upload, several are sent at a time, and each is retried on its own, so a large folder or a flaky connection doesn't start over. Progress is reported per file to clients that ask for it.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `directory` | string | Yes | Path of the local directory (or its `file://` URI); must be inside the allowed directories |
| `network` | `"public"` \| `"private"` | No | Upload to public or private IPFS (default: `"public"`) |
| `name` | string | No | Name of the folder, the top directory of every file path in it (default: the directory's name). When adding files to an existing folder, pass that folder's name |
| `group_id` | string | No | ID of a group to add the folder to |
| `keyvalues` | object | No | Metadata key-value pairs for the folder |
| `cidVersion` | `"v0"` \| `"v1"` | No | CID version of the folder and its files (default: `"v1"`) |
| `concurrency` | number | No | How many files send their bytes at the same time, 1 to 32 (default: 4) |
| `folderId` | string | No | ID of an existing folder to upload into: to send failed files again, or to add files. A file whose path is already in the folder replaces it |
| `paths` | string[] | No | Upload only these files: paths relative to the directory, with `/` separators. Defaults to every file |

Every regular file under the directory is uploaded, hidden files and empty files included. A symlink to a file is followed only when its target is inside the allowed directories; symlinks to directories, symlinks leaving the allowed directories, empty directories and names holding `%` are skipped and listed in the result.

When some files fail for good, the others stay in the folder, and the result lists the failed paths with their reasons (the first 50) and the arguments of a call that sends only the failed files again into the same folder (`folderId` and `paths`).

A folder holds at most `folder_max_files` files ([getUploadLimits](#getuploadlimits); 30,000 unless your account has its own limit). From `pinata-mcp` 0.5.0, a new folder of more files is refused before any file is sent, with the file count of each top-level subdirectory: upload the directory as several folders, one call per subdirectory. Files refused because a folder is full come with the arguments that upload them as a new folder instead.

Pinata accepts new files into a folder for 24 hours after its last upload; [listFolder](#listfolder) shows whether it still does (`appendable`, `appendable_until`).

**Example Prompts:**
```
Upload the folder ~/sites/blog to Pinata as a public folder

Upload ~/datasets/images to Pinata as a private folder named "training-images"

Add ~/sites/blog/posts/new.md to the folder I just uploaded
```

### listFolder

List one level of a folder: its files and subdirectories with their names, paths, sizes and CIDs, plus the folder's CID, its `root` (the name every file path starts with) and whether files can still be added to it (`appendable`, `appendable_until`).

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `folderId` | string | Yes | ID of the folder (the `id` returned by `uploadFolder`) |
| `network` | `"public"` \| `"private"` | No | Network the folder is on; when given, a folder on the other network is not found |
| `path` | string | No | Subdirectory to list, relative to the folder root, without the root name (e.g. `images/2024`). Defaults to the root |
| `limit` | number | No | Maximum number of entries, 1 to 1000 (default: 100) |
| `pageToken` | string | No | `next_page_token` of the previous page |

**Example Prompts:**
```
What's in the folder I uploaded to Pinata?

List the images/2024 directory of folder 019a8b2c-4d5e-7f60-8a1b-2c3d4e5f6a7b
```

## Signed Upload URLs

### createSignedUploadUrl

Create a presigned URL for client-side uploads without exposing your API key.

<Note>
  **Hosted server:** this is how the assistant uploads files and folders from your disk: it creates the URL, then sends the files with `curl` as multipart form data (one `file` field per file; for a folder, each named `<folder>/<path>` plus a `name` field, up to 150 files). `expires` is at most 24 hours, and `network` sets the network of every upload through the URL. When `allow_mime_types` is set, folder uploads stay allowed.
</Note>

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `expires` | number | Yes | How long the URL is valid in seconds |
| `max_file_size` | number | No | Max file size in bytes |
| `allow_mime_types` | string[] | No | Allowed MIME types (supports wildcards like `"image/*"`) |
| `group_id` | string | No | Group to add the uploaded file to |
| `filename` | string | No | Name for the uploaded file |
| `keyvalues` | object | No | Metadata key-value pairs |

**Example Prompt:**
```
Create a signed upload URL that expires in 5 minutes and only allows image uploads up to 10MB
```

### listAllowedDirectories

<Note>
  Local server only.
</Note>

List directories the MCP server can access for file operations.

**Parameters:** None

**Example Prompt:**
```
What directories can you access for file uploads?
```
